# Claude Code에 전달할 구현 지침

> 현재 초기 설계는 Codex가 담당한다. 이 문서는 추후 Claude Code에 구현을 맡길 경우 사용하는 전달용 지침이며 자동으로 작업을 위임하지 않는다.

아래 지침과 `ARCHITECTURE-V2.ko.md`, `REVIEW-CLAUDE-DESIGN.ko.md`를 함께 전달한다.

---

VMwareconnect의 기존 docs/00~09 설계를 첨부한 v2 구조에 맞춰 개정해줘. 검토 기준 커밋은 `49f760dde3326067fe2cde5ca8f6c5f7ccf868c2`이므로 현재 브랜치에 이후 변경이 있다면 먼저 차이를 확인하고 유지할 변경을 구분해줘.

목표는 Dataloy Operational 항차를 기준으로 VMware에서 접근 가능한 Outlook의 noon/port/working/SOF 보고를 자동 수집하고, 선박별 최신 보고 위치와 업무 상태, Dataloy 반영 차이를 근거와 함께 보여주는 dashboard야.

핵심 요구사항:

1. 자동 수집·파싱·대조는 스케줄러와 지속 작업 큐로 실행하고 Claude/MCP 대화의 유무에 의존하지 않게 해줘. 웹 API와 MCP는 같은 Application Service를 사용해줘.
2. 메일 접근은 Graph 가능 여부를 먼저 검증하고 COM은 Classic Outlook 사용자 세션에서만 조건부로 선택해줘. VMware/메일망/Dataloy의 연결 관계를 추측해서 확정하지 마.
3. 이메일 원문, 문서, 보고서 revision, 필드별 observation, 복수 operational_event를 분리해줘. SOF 한 통의 여러 사건, 정정·전달·중복·지연 보고를 보존해줘.
4. 선박시/항구시/UTC를 각 필드별로 구분해줘. 경도만으로 시간대를 확정하지 말고 미확정 시간은 시간 비교에서 보류해줘.
5. OPR은 화면의 관리 대상이야. 보고 매칭에는 이전/다음 항차를 포함하고 OPR이 하나라는 이유로 자동 귀속하지 마. 선박·항차·기항의 모호한 후보는 검토함으로 보내줘.
6. Dataloy 계획/예측, Dataloy 등록 실적, 본선 보고를 따로 보존해줘. ARRIVAL/EOSP, DEPARTURE/COSP, NOR 제출/수락을 의미 확인 없이 통합하지 마.
7. 소스 동기화 실패·부분 조회·미파싱 적체를 실제 보고 미수신 또는 Dataloy 미반영과 구별해줘. 비교 불가/유예 중/정보 부족 상태를 정상으로 표시하지 마.
8. 지도에는 관측시각과 출처가 있는 마지막 보고 위치를 표시해줘. AIS 없는 상태에서 실시간 위치로 표현하지 마. 근거 없는 추정 ETA·표류·만재 상태는 기본 비활성 또는 UNKNOWN으로 처리해줘.
9. 검토 이슈의 확인/해결/보류/재발을 구분하고 증거와 평가 이력을 유지해줘. 공유 배포의 로그인·선대별 권한·원문 접근 통제는 v1에 포함해줘.
10. Dataloy는 읽기 전용으로 유지하고 원문/자격증명을 Git에 넣지 마. 내부 검토 기록의 수정과 외부 시스템의 수정은 명확히 구별해줘.

첫 단계에서는 실제 환경의 접근성, Dataloy API field/event 계약, 익명화된 대표 메일 표본을 검증해줘. 접근 정보가 없으면 미확인 항목으로 기록하고 연결 성공을 주장하지 마. 개발 가능한 도메인 계약과 테스트 fixture 설계는 진행해도 돼.

다음으로 선박 3~5척을 대상으로 ‘자동 수집 → 위치/ETA → 대조 → 원문 근거’의 최소 수직 흐름을 구현해줘. 이후 SOF/작업 진행, 정정·지연 처리, 검토 수명주기, 팀 대시보드 순으로 확장해줘. 원래 문서를 모두 그대로 두고 별도의 상충 설계만 추가하지 말고, 각 문서의 결정·미확인 항목을 일관되게 정리해줘.

완료 보고에는 실제 검증한 환경, 변경 파일, 통과한 시나리오, 남은 미확인 전제를 분리해서 적어줘. ‘커버리지 높음’만으로 정확도를 주장하지 말고 선박/좌표/시각/이벤트 매칭의 오류와 놓친 사례도 보고해줘.
