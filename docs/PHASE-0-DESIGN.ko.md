# Phase 0 — 초기 설계 및 환경 검증

상태: 설계 진행 / 실제 환경 검증 대기. 작성: 2026-09-14.
설계 담당: Codex. 업무 의미 확인: 사용자 또는 운항 담당자. 접근 설정 확인: 해당 시스템 관리자.
설계 기준: [ARCHITECTURE-V2.ko.md](ARCHITECTURE-V2.ko.md).

## 목표와 완료 정의

선박 3~5척에 대해 승인된 Outlook 보고 수집 경로와 Dataloy 읽기 계약을 확인하고, 보고서에서 지도·항차 대조·근거 조회까지 연결되는 첫 구현의 명세를 확정한다.
현재 저장소 설계 검토만 완료했으며 VM·메일함·Dataloy 접속은 아직 검증하지 않았다.

완료 조건:

- 하나 이상의 실제 메일 수집 경로를 확인하고 실행 세션·네트워크·복구 조건을 기록한다.
- 실제 Dataloy 응답을 기준으로 Operational 범위, 항차/선박/기항 키, 시간 및 이벤트 의미를 확인한다.
- 익명화한 보고 표본에서 위치·ETA·SOF·working 데이터의 필드와 근거를 추적한다.
- 화면, 데이터 계약, 예외 처리, 테스트 사례가 동일한 용어와 상태를 사용한다.
- 미확인 값은 추측으로 구현하지 않고 차단되는 기능과 함께 남긴다.

위 계약 경로들은 예정 산출물이다. 아직 존재하지 않는 계약을 구현 완료 또는 테넌트 검증 완료로 취급하지 않는다.

## 환경 접근 전에도 진행 가능한 설계

- 도메인 모델, 상태 전이, 내부 issue 수명주기 및 수집 job 계약 구체화.
- 가상 보고를 이용한 UI 및 API 예시. 모든 예시는 가상 데이터임을 표시.
- 항차 전환, 지연 보고, 중복 SOF, 시간대 미상, 부분 수집 실패의 기대 결과 정의.

## 첫 구현의 범위

선박 3~5척, 선정된 mailbox/폴더, 검증된 주요 보고 양식을 대상으로 한다.
자동 수집 → 원문/버전 저장 → 위치 및 ETA 추출 → 선박/항차 귀속 → Dataloy 대조 → 지도/선박 표/근거 조회 순으로 연결한다.
Dataloy는 읽기 전용이고, 내부 검토 액션만 저장한다. SOF·working의 수량 의미가 확인되지 않은 경우 해당 필드는 검토 대기로 남긴다.
